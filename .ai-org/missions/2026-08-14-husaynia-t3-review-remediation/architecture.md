- **FACT:** `ApiProblemDetails` already has the required RFC 9457-compatible shape and media type: `type`, `title`, `status`, `code`, `detail`, `traceId`, optional `fieldErrors` (`ApiProblemDetailsMiddleware.cs:9-17,67-94`).
- **FACT:** The response trace ID is copied from `Activity.Current`, allowing an inbound W3C `traceparent` to choose the API-visible ID (`RequestTraceMiddleware.cs:6-18`).
- **FACT:** Body limiting already counts streamed requests with unknown `Content-Length`, buffers at most the endpoint limit, and returns `413` after the first excess chunk (`RequestBodyLimitMiddleware.cs:11-49`).
- **FACT:** Multi-partition rate acquisition is already atomic: all buckets are checked before any bucket is enqueued (`ApiRateLimitMiddleware.cs:62-97`).
- **FACT:** The contract suite currently covers snapshot equality, basic problem details, fixed-length bodies, and a single account partition, but not fail-closed auth, injected discovery, hostile `traceparent`, streamed bodies, or multi-partition isolation (`ApiConventionTests.cs:18-149`). - **FACT:** Only the shared framework and the existing xUnit/test packages are referenced; warnings are errors and builds are deterministic (`Directory.Build.props:3-9`; `Directory.Packages.props:6-10`).

## 2. Desired state

The host is default-deny, with both an authenticated fallback policy and explicit authorization on the versioned route group. OpenAPI `paths` are generated from the endpoints actually mapped into the running application, normalized deterministically, and compared read-only with the checked-in snapshot. HTTP enums use canonical camel-case strings, malformed/unexpected failures return fixed RFC 9457 bodies, and the API-visible trace ID is generated by the server.

No domain endpoint, database, authentication implementation, CORS policy, deployment setting, external service, or new package is introduced.

## 4. Frozen contracts

### 4.1 Authorization

```csharp
services.AddAuthorization(options =>
    options.FallbackPolicy = new AuthorizationPolicyBuilder()
        .RequireAuthenticatedUser()
        .Build());

RouteGroupBuilder api = application
    .MapGroup(ApiDefaults.BasePath)
    .RequireAuthorization();
```

- The placeholder bearer scheme accepts no credential and therefore returns `401`.
- Fallback protects endpoints outside the group, including `/openapi/v1.json`.
- T3 contains no anonymous endpoint. Future invitation acceptance, login, and refresh endpoints must opt out individually with `.AllowAnonymous()`; a broad anonymous group is forbidden.
- Existing CORS behavior remains closed: do not add `AddCors`, `UseCors`, or `Access-Control-Allow-Origin`.

### 4.2 Test injection

```csharp
public static WebApplication BuildApplication(
    WebApplicationOptions? options = null,
    Action<WebApplicationBuilder>? configureBuilder = null,
    Action<RouteGroupBuilder>? configureApi = null);
```

`configureApi` is a composition/test seam, not endpoint discovery. It is invoked on the already protected `/api/v1` group; injected endpoints therefore inherit authorization and appear in the same endpoint data source as production mappings.

### 4.3 OpenAPI

```csharp
public static string CreateJson(IEnumerable<EndpointDataSource> dataSources);
```

Deterministic normalization:

1. Flatten `EndpointDataSource.Endpoints`; select `RouteEndpoint` values with HTTP-method metadata.
2. Exclude `IExcludeFromDescriptionMetadata`; include only routes equal to or below `/api/v1`.
3. Strip `/api/v1` because it remains the document server URL; normalize the remaining route to a leading `/` and remove ASP.NET inline route constraints from `{parameter}` names.
4. Expand one operation per HTTP method. Sort paths with `StringComparer.Ordinal`; sort methods by `GET, POST, PUT, PATCH, DELETE, OPTIONS, HEAD`, then ordinal for any other method.
5. Use only stable metadata: route template, HTTP method, explicit endpoint name when present, route parameters, `IProducesResponseTypeMetadata`, and authorization/anonymous metadata. Never serialize registration order, delegate/display names, ports, timestamps, assembly-qualified names, or environment-specific values.
6. Emit a default response when no response metadata exists. Emit operation `security: []` only for an explicit `IAllowAnonymous` endpoint; otherwise root `bearerAuth` security applies.
7. Fail generation on a duplicate normalized `(path, method)` rather than selecting one nondeterministically.
8. Construct `JsonObject` properties in fixed order, use the existing indented serializer, normalize to LF, and end with one newline.

The Production-like snapshot is expected to retain empty `paths` until a real feature endpoint exists; the injected-endpoint test proves that emptiness is discovered rather than hard-coded. Snapshot tests are comparison-only and expose no update flag or write path.

### 4.4 JSON enums

- Canonical response representation is camel-case string, e.g. `MembershipStatus.Active` becomes `"active"`.
- Named string input uses the framework converter; numeric JSON tokens are rejected, including values not defined by the enum.
- Rejection is `400`, `application/problem+json`, code `bad_request`, with the fixed malformed detail below.
- Add `x-conventions.jsonEnums = "camelCaseStrings"` and `x-conventions.numericEnumsAccepted = false` to the snapshot.

### 4.5 Problems and logging

Retain the existing problem schema and `type` URI format. Freeze these new details:

| Failure | Status/code/title/detail |
|---|---|
| Malformed JSON/binding, including numeric enum | `400 / bad_request / Bad request / The request body is malformed or invalid.` |
| Unexpected exception before response start | `500 / internal_error / Internal server error / An unexpected error occurred.` |

- Never copy exception text, JSON parser text, request data, or stack traces into the client body.
- Log malformed requests at Warning and unexpected exceptions at Error with stable event IDs, `traceId`, method, path/endpoint, and exception server-side; do not enrich with bodies, query strings, authorization headers, or tokens.
- If the response has started, log and rethrow because a valid problem body can no longer be guaranteed.
- A cancellation caused by `RequestAborted` is not converted into `500`.
- Status-code problem synthesis continues for `/api/v1` and is extended to `/openapi/v1.json`.

### 4.6 Trace ID

- `X-Trace-Id` and problem `traceId` are the same fresh 32-character lowercase hexadecimal server ID.
- Inbound `traceparent` may remain available to platform distributed tracing, but it cannot select the API-visible ID.
- Inbound `X-Trace-Id` is ignored.

### 4.7 Request limits and rate limits

Production algorithms and configured limits do not change. Testing adds one protected endpoint with account limit `1/minute` and organization limit `2/minute` solely to prove that a rejected multi-partition acquisition consumes no non-exhausted bucket.

## 5. Cross-cutting behavior

- **Security boundary:** authentication/authorization executes before body/rate endpoint work; JSON validation occurs at the HTTP boundary; all current endpoints are protected.
- **Concurrency:** OpenAPI generation uses request-local JSON nodes. Existing locked, check-then-enqueue rate acquisition remains atomic.
- **Idempotency/data:** no business mutation, persistence, schema, or idempotency contract changes.
- **Failure model:** invalid endpoint metadata fails OpenAPI generation and the snapshot/discovery tests; it does not silently publish a partial contract. A started response cannot be rewritten and is aborted after logging.
- **Resource bounds:** unknown-length bodies retain the existing maximum 12 KiB endpoint buffer bound; no unbounded buffering is introduced.
- **Observability:** server-owned trace IDs correlate response problems and middleware logs; no telemetry vendor or sink is added.

## 6. Test mapping

### Seven missing independent probes

1. `AuthorizationFailsClosedForVersionedAndFallbackEndpoints` — default placeholder host; fake bearer or no credential receives `401` problem from a convention endpoint and `/openapi/v1.json`; no current endpoint has `IAllowAnonymous`.
2. `InjectedEndpointAppearsInGeneratedOpenApi` — inject `GET /api/v1/_contract/injected`; authenticated OpenAPI contains `/_contract/injected` and `get`.
3. `InboundTraceparentCannotChooseResponseTraceId` — send a known W3C trace ID; response/problem IDs match each other and differ from the inbound ID.
4. `StreamedBodyWithoutContentLengthAcceptsExactLimit` — custom streaming content reports unknown length and sends exactly the configured bytes; result is `204`.
5. `StreamedBodyWithoutContentLengthRejectsLimitPlusOne` — same transport sends one extra byte; result is safe `413 payload_too_large`.
6. `RejectedAccountPartitionDoesNotConsumeOrganizationPartition` — an account-exhausted request is rejected; another account in the same organization can still use the remaining organization permit.
7. `RejectedOrganizationPartitionDoesNotConsumeAccountPartition` — an organization-exhausted request is rejected; the same untouched account succeeds in a different organization.

### Additional remediation tests

- Production-like OpenAPI is byte-for-byte deterministic across requests and equals the checked-in read-only snapshot.
- Valid enum request `"active"` binds and the response serializes `"active"`; undefined numeric input returns the fixed `400` problem.
- Malformed JSON does not expose parser text.
- A Testing-only endpoint throwing an exception returns the fixed `500` problem, logs one Error event with the response trace ID, and does not expose the exception sentinel.
- Existing fixed-length body, single-partition rate, pagination, status problem, and frozen convention tests remain; none are deleted or weakened.

## 7. Tradeoffs and rejected alternatives

- **Chosen:** shared-framework `EndpointDataSource` metadata plus the existing JSON builder. This is the smallest correction and adds no dependency.  
  **Rejected:** Swashbuckle/NSwag or a new OpenAPI package; no T3 requirement needs their schema pipeline, and adding one now increases package and generated-output churn.
- **Chosen:** group authorization plus fallback policy. The duplication is intentional defense in depth: group metadata documents the versioned contract, while fallback protects future endpoints mapped elsewhere.  
  **Rejected:** fallback only or endpoint-by-endpoint authorization; both make omissions easier.
- **Chosen:** built-in `JsonStringEnumConverter` with all numeric values disabled.  
  **Rejected:** a custom strict-case converter; canonical output and numeric rejection are required, but case-sensitive input is not.
- **Chosen:** keep platform `Activity` tracing separate from the server-owned API correlation ID.  
  **Rejected:** echoing `Activity.TraceId`; inbound `traceparent` controls it.
- **Chosen:** explicit snapshot review.  
  **Rejected:** approval/update switches in tests; they permit contract drift to rewrite its own evidence.

## 8. Migration and rollback

There is no data migration. No implemented feature endpoint currently exposes an enum, and the repository identifies this as a foundation without business behavior, so the string-enum and authorization changes do not break a deployed T4 contract and need no CTO exception.

Forward: implement middleware/configuration first, adapt the authenticated test host, generate the Production-like document once, review and check in the snapshot, then run the full quality gates. Rollback: revert API code, tests, and snapshot together; no stored data or infrastructure remains to unwind.

## 9. Risks and mitigations

- **Incomplete future schemas:** the T3 generator intentionally documents only metadata currently available. Mitigation: T4 endpoints must add explicit typed request/response metadata; expanding schema generation is a separate reviewed change.
- **Protected OpenAPI surprises tooling:** mitigation is in-process authenticated contract generation; public anonymous documentation is not an approved requirement.
- **Endpoint metadata collision:** deterministic generation fails rather than publishing an arbitrary operation; contract tests expose the collision before merge.
- **Response-started exception:** a problem body is impossible after headers/body begin; log and abort, and keep streaming endpoints responsible for pre-write validation.
- **Trace vocabulary:** platform trace ID and API `traceId` differ by design; logs must label the latter consistently as the API request correlation ID.

## 10. Implementation boundary

The Tech Lead should decompose one API/configuration slice, one OpenAPI/snapshot slice, and one contract-test slice, with the API contracts above frozen between them. Do not start T4 domain, persistence, real authentication, mobile, deployment, or infrastructure work.
